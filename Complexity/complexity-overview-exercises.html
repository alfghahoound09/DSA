Tại sao cần phân tích thuật toán?

Hai thuật toán cùng giải một bài toán nhưng có thể chênh lệch tốc độ hàng triệu lần khi dữ liệu lớn.

🎯 Mục đích phân tích

⏱️

Time Complexity

Đo thời gian chạy (số bước thực hiện) tăng thế nào khi input lớn dần.

💾

Space Complexity

Đo bộ nhớ cần dùng tăng thế nào khi input lớn dần.

📏

Không phụ thuộc phần cứng

Đo bằng số bước trừu tượng, không phải giây — kết quả đúng trên mọi máy.

📈

Dự đoán hiệu năng

Biết thuật toán có scale được không khi n = 10⁶, 10⁹...

📐 Ba ký hiệu tiệm cận (Asymptotic Notations)

O

Big-O (Upper Bound)

Cận trên — worst case. "Chậm nhất thì cỡ này".

f(n) ≤ c·g(n), ∀ n ≥ n₀
Ω

Big-Omega (Lower Bound)

Cận dưới — best case. "Nhanh nhất cũng phải cỡ này".

f(n) ≥ c·g(n), ∀ n ≥ n₀
Θ

Big-Theta (Tight Bound)

Cận chặt — kẹp giữa. "Chính xác tăng theo tốc độ này".

c₁·g(n) ≤ f(n) ≤ c₂·g(n)
💡 Trong thực tế, Big-O được dùng nhiều nhất vì ta quan tâm worst case — "thuật toán này chậm nhất cỡ nào?"

🔧 Quy tắc tính Big-O nhanh

① Bỏ hằng số

3n + 5 → O(n)
Hằng số không quan trọng khi n lớn.

② Giữ bậc cao nhất

n² + 100n + 99 → O(n²)
Bậc thấp hơn trở nên vô nghĩa.

③ Vòng lặp lồng = nhân

2 vòng for lồng nhau mỗi vòng n lần → O(n²)

④ Nối tiếp = cộng → giữ max

O(n) + O(n²) → O(n²)
Đoạn chậm nhất quyết định.

⑤ Chia đôi = log n

Mỗi bước chia đôi input → O(log n)
VD: Binary Search.

⑥ Đệ quy: dùng cây

Vẽ cây đệ quy, đếm tổng số node × work mỗi node. Hoặc dùng Master Theorem.

💻 Nhận diện Big-O qua code

O(1) — Constant 
// Truy cập mảng, phép gán, so sánh
int x = arr[5];           // 1 bước duy nhất
return stack.peek();       // O(1)
O(n) — Linear 
// 1 vòng lặp chạy n lần
for (int i = 0; i < n; i++) {
    sum += arr[i];            // n bước
}
O(n²) — Quadratic 
// 2 vòng lặp lồng nhau, mỗi vòng n lần
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        // n × n = n² bước
    }
}
O(log n) — Logarithmic 
// Mỗi bước chia đôi phạm vi
while (lo <= hi) {
    int mid = (lo + hi) / 2;
    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) lo = mid + 1;
    else hi = mid - 1;    // chia đôi → log₂ n bước
}
