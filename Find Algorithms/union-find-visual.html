Quick Find & Union Find

Giải thích trực quan về cấu trúc dữ liệu Union-Find — từ ý tưởng cơ bản đến tối ưu hóa nâng cao, với animation tương tác.

🧩 Bài Toán Dynamic Connectivity

Cho N đối tượng, thực hiện hai thao tác: Union (nối hai đối tượng) và Find/Connected (kiểm tra hai đối tượng có liên thông không).

🎯 Tại sao cần Union-Find?

Ứng dụng thực tế

  • Mạng máy tính: Kiểm tra hai máy tính có kết nối được với nhau không
  • Mạng xã hội: Hai người có thuộc cùng nhóm bạn bè không
  • Xử lý ảnh: Nhận diện vùng liên thông trong ảnh
  • Thuật toán Kruskal: Tìm cây khung nhỏ nhất (MST)
  • Game: Kiểm tra thắng trong trò chơi Hex

📐 API Cơ Bản (Interface)

Java public class UnionFind { // Khởi tạo N đối tượng (0 đến N-1) public UnionFind(int N) // Nối đối tượng p và q vào cùng một nhóm public void union(int p, int q) // Kiểm tra p và q có liên thông không public boolean connected(int p, int q) }

💡 Tính chất quan hệ tương đương

  • Phản xạ: p liên thông với chính p
  • Đối xứng: Nếu p liên thông với q → q liên thông với p
  • Bắc cầu: Nếu p↔q và q↔r → p↔r

💡 Ý Tưởng Core: Component ID

Mỗi đối tượng thuộc một "nhóm liên thông" (connected component). Ta lưu mảng id[] để biết mỗi đối tượng thuộc nhóm nào.

Ban đầu mỗi phần tử là component riêng: id[i] = i

⚡ Quick Find (Eager Approach)

Tìm nhanh nhưng Union chậm — "Quick Find" hy sinh tốc độ union để có find tức thì.

🧠 Ý Tưởng Cốt Lõi

Cấu trúc dữ liệu

Dùng mảng id[] có kích thước N. Quy tắc: p và q liên thông ⟺ id[p] == id[q]

🔍 Find (Connected) — O(1)

Chỉ cần so sánh: return id[p] == id[q]. Cực kỳ nhanh, chỉ 1 phép so sánh!

🔗 Union — O(N)

Để nối p với q: duyệt toàn bộ mảng, đổi tất cả phần tử có id[i] == id[p] thành id[q]. Đây là nhược điểm lớn — mỗi lần union phải quét N phần tử!

Initialize
O(N)
Find
O(1)
Union
O(N)
N union trên N phần tử
O(N²)

💻 Code Java

Java public class QuickFindUF { private int[] id; // Khởi tạo: mỗi phần tử là component riêng public QuickFindUF(int N) { id = new int[N]; for (int i = 0; i < N; i++) id[i] = i; // id[i] = i ban đầu } // Find: p và q liên thông ⟺ cùng id public boolean connected(int p, int q) { return id[p] == id[q]; // O(1) ✨ } // Union: đổi TẤT CẢ id[p] thành id[q] public void union(int p, int q) { int pid = id[p], qid = id[q]; // lưu lại giá trị for (int i = 0; i < id.length; i++) if (id[i] == pid) id[i] = qid; // đổi tất cả → O(N) 🐢 } }

⚠️ Nhược Điểm Nghiêm Trọng

Quá chậm cho dữ liệu lớn

Với N = 10⁹ (1 tỷ) phần tử và N lệnh union → cần ~10¹⁸ thao tác. Với tốc độ 10⁹ ops/giây → mất ~30 năm! Quick Find không scalable.

🌳 Quick Union (Lazy Approach)

Cải tiến: biểu diễn bằng cây — union nhanh hơn nhưng find có thể chậm.

🧠 Ý Tưởng Cốt Lõi

Cấu trúc dữ liệu: Forest of Trees

Mảng parent[] (hay id[]): id[i] là cha của i. Gốc (root) của cây là phần tử có id[i] == i.

🔍 Find (Root) — O(N) worst case

Đi từ i lên cha, lên ông, ... cho đến khi gặp gốc: while (id[i] != i) i = id[i];

🔗 Union — O(N) worst case

Tìm gốc của p và q. Nếu khác nhau → gắn gốc p làm con của gốc q: id[root_p] = root_q. Chỉ thay đổi 1 phần tử trong mảng!

Initialize
O(N)
Find (root)
O(N)*
Union
O(N)*
* Worst case
Khi cây bị skewed

💻 Code Java

Java public class QuickUnionUF { private int[] id; // id[i] = parent of i public QuickUnionUF(int N) { id = new int[N]; for (int i = 0; i < N; i++) id[i] = i; // mỗi node là gốc của chính nó } // Tìm gốc: đi lên cho đến khi id[i] == i private int root(int i) { while (id[i] != i) i = id[i]; // leo lên cha return i; } // Connected: cùng gốc ⟺ liên thông public boolean connected(int p, int q) { return root(p) == root(q); } // Union: gắn gốc p vào gốc q public void union(int p, int q) { int rootP = root(p); int rootQ = root(q); id[rootP] = rootQ; // 1 thao tác gán ✨ } }

⚠️ Vấn Đề: Cây Có Thể Bị "Cao" (Tall Trees)

Worst case: Chuỗi liên kết dài

Nếu union theo thứ tự xấu (0-1, 1-2, 2-3, ...), cây sẽ thành danh sách liên kết (chiều cao = N-1). Khi đó find phải duyệt N bước → cũng O(N²) cho N thao tác!

⚖️ Weighted Quick Union + Path Compression

Hai cải tiến then chốt biến Union-Find thành thuật toán gần như O(1) cho mỗi thao tác.

🧠 Cải Tiến 1: Weighted (Union by Size/Rank)

Ý tưởng: Luôn gắn cây nhỏ vào cây lớn

Thêm mảng size[] đếm số node của mỗi cây. Khi union, cây nhỏ hơn sẽ được gắn vào gốc cây lớn hơn. Điều này đảm bảo chiều cao cây ≤ lg(N) (logarit cơ số 2).

📏 Tại sao chiều cao ≤ lg(N)?

Chiều sâu của node x chỉ tăng khi cây chứa x bị merge vào cây lớn hơn (kích thước ≥ gấp đôi). Điều này chỉ xảy ra tối đa lg(N) lần → chiều sâu tối đa = lg(N).

🧠 Cải Tiến 2: Path Compression

Ý tưởng: "Làm phẳng" cây khi tìm gốc

Khi tìm gốc của node i, trên đường đi lên, ta trỏ mỗi node trực tiếp lên gốc (hoặc lên ông nội). Hai cách phổ biến:

  • One-pass (Halving): id[i] = id[id[i]] — trỏ lên ông nội, giảm chiều cao ~50%
  • Two-pass (Full): Tìm gốc trước, rồi trỏ tất cả node trên đường đi thẳng vào gốc
Initialize
O(N)
Find
O(α(N))*
Union
O(α(N))*
* α(N)
Inverse Ackermann
≤ 5 thực tế

💻 Code Java — Weighted QU + Path Compression

Java public class WeightedQuickUnionUF { private int[] id; // parent[i] = cha của i private int[] size; // size[i] = số node trong cây gốc i public WeightedQuickUnionUF(int N) { id = new int[N]; size = new int[N]; for (int i = 0; i < N; i++) { id[i] = i; size[i] = 1; } } // Tìm gốc + Path Compression (halving) private int root(int i) { while (id[i] != i) { id[i] = id[id[i]]; // ⚡ path compression! i = id[i]; } return i; } public boolean connected(int p, int q) { return root(p) == root(q); } // Weighted Union: cây nhỏ → gắn vào cây lớn public void union(int p, int q) { int rootP = root(p); int rootQ = root(q); if (rootP == rootQ) return; // ⚖️ Gắn cây nhỏ vào cây lớn if (size[rootP] < size[rootQ]) { id[rootP] = rootQ; size[rootQ] += size[rootP]; } else { id[rootQ] = rootP; size[rootP] += size[rootQ]; } } }

📊 So Sánh Các Thuật Toán

Tổng kết sự khác biệt về hiệu năng giữa các biến thể Union-Find.

📋 Bảng So Sánh Độ Phức Tạp

Thuật Toán Initialize Union Find N thao tác trên N phần tử
Quick Find N N 1 N²
Quick Union N N* N* N²
Weighted QU N lg N lg N N lg N
WQU + Path Comp. N α(N)* α(N)* N α(N) ≈ N

📝 Ghi chú

  • * worst case — khi cây bị lệch thành danh sách liên kết
  • α(N) = hàm nghịch đảo Ackermann, tăng CỰC kỳ chậm (≤ 5 với mọi N thực tế, kể cả N = 265536)
  • lg N = log₂(N)

🏁 Kết Luận — Chọn Thuật Toán Nào?

✅ Luôn dùng Weighted Quick Union + Path Compression

Đây là implementation chuẩn. Code đơn giản, hiệu năng gần như tối ưu lý thuyết O(N α(N)).

  • 🚫 Quick Find: Union quá chậm O(N) — không dùng cho dữ liệu lớn
  • 🚫 Quick Union thuần: Cây có thể bị cao → find chậm O(N)
  • ✅ Weighted QU: Đảm bảo chiều cao ≤ lg(N)
  • ✅✅ Weighted QU + Path Compression: Gần như O(1) amortized
