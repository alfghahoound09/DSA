1. Phân tích Thuật toán & Độ phức tạp (Algorithm Complexity)

Ký hiệu xấp xỉ Tilde (~), Big-O, Big-Omega, Big-Theta, Memory Analysis 64-bit & 10 Code Patterns kinh điển

Phần 1 · Định nghĩa & Giải thích Các khái niệm cốt lõi trong phân tích thuật toán

〰️ Ký hiệu Tilde (~)

Giữ lại số hạng bậc cao nhất kèm hệ số dẫn đầu, bỏ các số hạng bậc thấp.

f(N) ~ g(N) ⇔ lim f(N)/g(N) = 1

VD: ½N² - 3N + 10 ~ ½N²

Θ Big-Theta (Tight Bound)

Bậc tăng trưởng chính xác (Order of Growth): bỏ cả hệ số dẫn đầu lẫn bậc thấp.

c₁·g(N) ≤ f(N) ≤ c₂·g(N)

VD: 2N² + 6N log N ∈ Θ(N²)

O Big-Oh (Upper Bound)

Cận trên tiệm cận (không vượt quá tốc độ tăng của g(N)).

f(N) ≤ c·g(N) với ∀ N ≥ N₀

⚠️ Toán học: 2N² vừa là O(N²), vừa là O(N³)!

Ω Big-Omega (Lower Bound)

Cận dưới tiệm cận (ít nhất cũng tăng nhanh cỡ g(N)).

f(N) ≥ c·g(N) với ∀ N ≥ N₀

⚠️ Toán học: 2N² vừa là Ω(N²), vừa là Ω(N), Ω(log N)!

📏 Quy tắc tính nhanh & Bẫy đề thi (COS226)

  • Mô hình chi phí (Cost Model): Đếm số lần thực hiện thao tác cơ bản chiếm nhiều thời gian nhất (phép so sánh compareTo, truy cập mảng a[i], hoặc lệnh op()).
  • Bẫy ký hiệu trong bài thi: Nếu đề hỏi hàm f(n) = 2n² + 2n + 6 log₂n thuộc tập nào: nó thuộc Θ(n²), O(n²), O(n³), Ω(n²), Ω(n), Ω(log n)! Chỉ có Θ là kẹp chặt đúng bậc.
  • Định luật lũy thừa (Doubling Hypothesis): Nếu T(N) ~ a·Nᵇ thì tỉ số T(2N) / T(N) ≈ 2ᵇ (tăng gấp 2 → b=1 tuyến tính; gấp 4 → b=2 bậc hai; gấp 8 → b=3 bậc ba).

💾 Phân tích bộ nhớ (64-bit Java Memory Model)

  • Primitive types: boolean, byte (1B), char, short (2B), int, float (4B), long, double (8B).
  • Object overhead: 16 bytes cho mỗi đối tượng + 8 bytes cho mỗi tham chiếu (reference pointer). Luôn làm tròn lên bội số của 8 bytes (padding).
  • Inner class (non-static): Tốn thêm 8 bytes ẩn trỏ về đối tượng lớp ngoài (vd private class Node trong BST).
  • Array: 24 bytes header + kích thước phần tử × N (làm tròn 8B).

Phần 2 · Code Patterns 10 Mẫu Code Pattern tính Tilde (~) & Big-Theta (Θ) hay gặp nhất

Dưới đây là toàn bộ các mẫu vòng lặp từ đơn giản đến bẫy kinh điển trong bài tập & đề thi (quét từ 1.4. AlgorithmAnalysis.pdf). Nhìn vào bước nhảy của biến chạy để suy ra ngay công thức xấp xỉ ~ và bậc tăng Θ:

① Vòng lặp đơn bước nhảy hằng số (+k)
~ (1/k) N Θ(N) 
for (int i = 10; i < n + 5; i += 2)
    op(); // chạy ~ n/2 lần → Θ(n)

Biến i tăng thêm 2 mỗi bước trên đoạn dài ~n → số lần gọi op() là ~ ½n.

② Vòng lặp nhân/chia hằng số (*2, /2)
~ log₂ N Θ(log N) 
for (int i = 1; i <= n * n * n; i *= 2)
    op(); // 2^k ≤ n³ ⇒ k ≈ log₂(n³) = 3 log₂ n

Mỗi bước nhân đôi cho tới n³ → số bước là ~ 3 log₂ n, bậc tăng trưởng vẫn là Θ(log n).

③ Vòng lặp lồng với giới hạn hằng số
~ 100 N Θ(N) 
for (int i = 0; i < n; i++)
    for (int j = 0; j < 100; j++)
        op(); // n × 100 = 100n → Θ(n), KHÔNG phải n²!

Vòng trong chạy đúng 100 lần (không phụ thuộc n) → tổng số phép toán chỉ tuyến tính ~ 100n.

④ Vòng lặp Tuyến tính × Chia đôi
~ N log₂ N Θ(N log N) 
for (int i = 0; i < n; i++)
    for (int j = 1; j < n; j *= 2)
        op(); // độc lập: n × log₂ n

Hai vòng lặp độc lập: vòng ngoài chạy n lần, vòng trong chạy log₂ n lần → nhân lại ra ~ n log₂ n.

⑤ Vòng lặp Tam giác (Phụ thuộc j = i + 1)
~ ½ N² Θ(N²) 
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        op(); // (n-1) + (n-2) + ... + 0 = n(n-1)/2 ~ ½n²

Số cặp lấy 2 phần tử từ n phần tử: C(n, 2) = n(n-1)/2 ~ ½n². Xuất hiện trong Selection Sort, 2-Sum.

⑥ BẪY CẤP SỐ NHÂN 1 (Geometric Series Trap)
~ N hoặc ~ 2N Θ(N) 
for (int i = 1; i < N; i *= 2)
    for (int j = 0; j < i; j++)
        sum++; // 1 + 2 + 4 + 8 + ... + N/2 = N - 1 ~ N

🔥 Bẫy hay sai nhất: Vòng trong chạy tới i (không phải N!). Tổng cấp số nhân 1 + 2 + 4 + ... + N/2 ~ N → chỉ là Θ(N) chứ không phải N log N!

⑦ BẪY CẤP SỐ NHÂN 2 (Giảm nửa mỗi vòng)
~ 2N Θ(N) 
for (int n = N; n > 0; n /= 2)
    for (int i = 0; i < n; i++)
        sum++; // N + N/2 + N/4 + ... + 1 ~ 2N → Θ(N)

🔥 Tổng N(1 + 1/2 + 1/4 + ...) = 2N. Chỉ chạy tuyến tính ~ 2N!

⑧ Vòng lặp Căn bậc hai (i * i < n)
~ √N log₃ N Θ(√N log N) 
for (int i = 0; i * i < n; i++)
    for (int j = 1; j < n; j *= 3)
        op(); // i < √n (chạy √n lần) × log₃ n

Điều kiện i * i < n tương đương i < √n. Nhân với vòng trong log₃ n.

⑨ Vòng lặp 3-Sum / Tổ hợp chập 3 hoặc 4
~ ⅙ N³ Θ(N³) 
for (int i = 0; i < n; i++)
  for (int j = i + 1; j < n; j++)
    for (int k = j + 1; k < n; k++)
      op(); // C(n,3) = n(n-1)(n-2)/6 ~ ⅙ n³

Tổng quát: d vòng lặp tăng dần phụ thuộc nhau (i < j < k...) sẽ chạy C(n, d) ~ nᵈ / d! lần.

⑩ Tổ hợp đề thi Midterm (n² kết hợp log)
~ ½ N⁴ log₂ N Θ(N⁴ log N) 
for (int i = 0; i < n*n; i++)
  for (int j = i+1; j < n*n; j++)
    for (int k = 1; k <= n*n; k *= 2) op();

2 vòng đầu với M = n² chạy ~ ½ M² = ½ n⁴ lần. Vòng trong chạy log₂(n²) = 2 log₂ n lần. Nhân lại: ½ n⁴ × 2 log₂ n = ~ n⁴ log₂ n!

2. Stack (Ngăn xếp) & Queue (Hàng đợi)

LIFO vs FIFO, cài đặt bằng Resizing Array / Circular Array và Linked List

Phần 1 · Định nghĩa & Giải thích Bản chất Stack (LIFO) & Queue (FIFO)

📥 Stack — Ngăn xếp (LIFO: Last In, First Out)

Phần tử được thêm vào SAU CÙNG sẽ được lấy ra ĐẦU TIÊN (thêm đầu - xóa đầu). Giống chồng đĩa hoặc nút Undo (Ctrl+Z).

  • push(item): Thêm phần tử vào đỉnh (top) — O(1)*
  • pop(): Lấy và xóa phần tử ở đỉnh (top) — O(1)*
  • peek(): Xem phần tử ở đỉnh mà không xóa — O(1)
  • Ứng dụng: Call Stack đệ quy, DFS, kiểm tra dấu ngoặc hợp lệ, tính biểu thức hậu tố (Postfix / thuật toán 2-stack của Dijkstra).

🚶 Queue — Hàng đợi (FIFO: First In, First Out)

Phần tử được thêm vào ĐẦU TIÊN sẽ được lấy ra ĐẦU TIÊN (thêm cuối rear - xóa đầu front). Giống xếp hàng mua vé.

  • enqueue(item): Thêm phần tử vào cuối hàng (rear) — O(1)*
  • dequeue(): Lấy và xóa phần tử ở đầu hàng (front) — O(1)*
  • peek(): Xem phần tử ở đầu hàng — O(1)
  • Ứng dụng: Duyệt theo chiều rộng (BFS), lập lịch tiến trình CPU, bộ đệm dữ liệu (Buffer / Print Queue).

3. Các Thuật Toán Sắp Xếp (Sorting Algorithms)

                        
Selection Sort, Insertion Sort, Shellsort, Merge Sort, Quick Sort (2-way & 3-way) & Heapsort

                    

                

            


            
            

                

                    
Phần 1 · Định nghĩa & Giải thích Nguyên lý cốt lõi & Bảng đối chiếu 6 thuật toán Sort

                


                

                    

                        
🔴 Selection Sort

                        
Ở bước i, quét phần còn lại [i..N-1] tìm phần tử nhỏ nhất (min) rồi đổi chỗ với a[i].

                        
    
                            
  • Số phép so sánh cố định ~ N²/2 (không phụ thuộc đầu vào).
    • 
                            
  • Số lần hoán đổi (swap) ít nhất: chỉ N lần!
    • 
                            
  • Không ổn định (Unstable) vì swap nhảy xa.
    • 
                        

                    


                    

                        
🟢 Insertion Sort

                        
Ở bước i, đưa a[i] lùi dần sang trái (đổi chỗ với phần tử đứng trước nếu nhỏ hơn) cho tới khi đúng vị trí.

                        
    
                            
  • Adaptive: Dừng sớm ngay khi gặp phần tử ≤ a[j]. Nếu mảng đã sắp hoặc gần sắp (số nghịch thế inversions tuyến tính) → chạy trong O(N)!
    • 
                            
  • Ổn định (Stable), dùng làm cutoff cho Merge/Quick Sort khi mảng con nhỏ (≤ 7..15).
    • 
                        

                    


                    

                        
🔵 Shellsort

                        
Thực hiện Insertion Sort với khoảng cách bước nhảy h (tạo mảng h-sorted). Giảm dần h về 1 theo dãy Knuth h = 3h + 1 (1, 4, 13, 40...).

                        
    
                            
  • Đưa phần tử đi xa ở các bước h lớn, khi h=1 mảng đã gần sắp xếp xong.
    • 
                            
  • Độ phức tạp thực tế ~ O(N^{3/2}), in-place, không stable.
    • 
                        

                    


                    

                        
🔷 Merge Sort (Top-down & Bottom-up)

                        
Chia để trị: Chia đôi mảng thành 2 nửa, đệ quy sắp xếp từng nửa, rồi trộn (merge) 2 nửa đã sắp bằng mảng phụ aux[].

                        
    
                            
  • Đảm bảo O(N log N) (tối đa N lg N compares) trong mọi trường hợp!
    • 
                            
  • Stable (khi aux[i] == aux[j] luôn lấy bên trái aux[i++] trước).
    • 
                            
  • Nhược điểm: tốn bộ nhớ phụ O(N) (không in-place).
    • 
                        

                    


                    

                        
🟠 Quick Sort & 3-Way Partition

                        
Xáo trộn ngẫu nhiên (shuffle), chọn v = a[lo] làm pivot, phân hoạch (partition) sao cho bên trái ≤ v, bên phải ≥ v, rồi đệ quy 2 bên.

                        
    
                            
  • Trung bình ~ 1.39 N lg N compares nhưng chạy thực tế nhanh nhất nhờ vòng lặp trong cực gọn & thân thiện bộ nhớ đệm (cache).
    • 
                            
  • Worst-case ~ N²/2 (khi mảng đã sắp hoặc toàn khóa trùng mà không dùng 3-way).
    • 
                            
  • Dijkstra 3-Way: Chia thành < v, == v, > v → chạy O(N) khi có nhiều khóa trùng lặp!
    • 
                        

                    


                    

                        
🟣 Heapsort

                        
Biến mảng thành Max-Heap ngay tại chỗ (Bottom-up sink từ N/2 về 1), sau đó lặp lại việc đổi phần tử lớn nhất ở gốc a[1] xuống cuối mảng và gọi sink(1).

                        
    
                            
  • Vừa đảm bảo O(N log N) worst-case, vừa In-place O(1) bộ nhớ phụ!
    • 
                            
  • Không stable, truy cập bộ nhớ nhảy cóc (cache kém hơn Quick Sort).
    •

4. Binary Heap & Hàng đợi ưu tiên (Priority Queue)

Phần 1 · Định nghĩa & Giải thích Cấu trúc Binary Heap & Nguyên lý Swim / Sink

                


                

                    

                        
🔺 Định nghĩa Binary Heap

                        
Là biểu diễn mảng của một Cây nhị phân hoàn chỉnh (Complete Binary Tree) thỏa mãn thứ tự Heap (Heap-ordered):

                        
    
                            
  • Max-Heap: Khóa của mọi nút cha ≥ khóa của 2 nút con (Phần tử lớn nhất luôn ở gốc pq[1]).
    • 
                            
  • Min-Heap: Khóa của mọi nút cha ≤ khóa của 2 nút con (Phần tử nhỏ nhất luôn ở gốc pq[1]).
    • 
                            
  • Chiều cao cây hoàn chỉnh có N nút luôn đúng bằng ⌊lg N⌋.
    • 
                        

                    


                    

                        
🔢 Công thức chỉ số mảng (1-indexed vs 0-indexed)

                        
Chuẩn Sedgewick (1-indexed, bỏ trống pq[0]):

                        
Cha của k = ⌊k/2⌋  |  Con trái = 2k  |  Con phải = 2k + 1

                        
Nếu dùng 0-indexed (đặt gốc tại pq[0] - Bài 2.4.10):

                        
Cha của k = ⌊(k-1)/2⌋  |  Con trái = 2k+1  |  Con phải = 2k+2

                    


                    

                        
🏊 Hai thao tác khôi phục thứ tự Heap

                        
    
                            
  • swim(k) (Bơi lên / Bottom-up): Khi nút k lớn hơn cha k/2 → đổi chỗ k ↔ k/2 lặp lại đến khi ≤ cha hoặc chạm gốc 1. Dùng cho insert(x) (đặt cuối mảng rồi swim(N)): tối đa 1 + lg N compares.
    • 
                            
  • sink(k) (Chìm xuống / Top-down): Khi nút k nhỏ hơn con → đổi chỗ với con LỚN HƠN trong 2 con 2k, 2k+1. Dùng cho delMax() (đổi pq[1] ↔ pq[N--] rồi sink(1)): tối đa 2 lg N compares.
    • 
                        

                    

                


                

                    

                        

                            
                                

                                    Cách cài đặt Priority Queue
                                    insert()
                                    delMax()
                                    max()
                                    Khi nào tốt nhất? (Bài 2.4.11 - 2.4.12)
                                

                            
                            
                                

                                    Mảng không sắp (Unordered Array)
                                    O(1)
                                    O(N)
                                    O(N)
                                    Rất nhiều insert nhưng cực ít delMax.
                                

                                

                                    Mảng có sắp (Ordered Array)
                                    O(N)
                                    O(1)
                                    O(1)
                                    Rất nhiều max/delMax nhưng cực ít insert.
                                

                                

                                    Binary Heap
                                    O(log N)
                                    O(log N)
                                    O(1)
                                    Chuẩn tối ưu tổng quát khi trộn lẫn hàng triệu insert & delMax.
                                

                            
                        

                    


                    

                        
🎯 Mẹo giải nhanh các câu hỏi kinh điển trong đề thi Heap

                        
    
                            
  • Mảng giảm dần có phải Max-Heap không? (Bài 2.4.4): CÓ! Vì nếu a[1] ≥ a[2] ≥ ... ≥ a[N] thì với mọi k, a[k] ≥ a[2k] và a[k] ≥ a[2k+1] luôn đúng!
    • 
                            
  • Tìm Top-K phần tử lớn nhất trong chuỗi N phần tử cực lớn (Bài 2.4.17): Dùng một Min-Heap kích thước K! Khi phần tử mới đến, chèn vào rồi gọi delMin() để loại bỏ số nhỏ nhất → còn lại đúng K số lớn nhất với thời gian O(N log K) và bộ nhớ O(K).
    • 
                            
  • Running Median (Trung vị động - Bài 5): Dùng 2 Heap: Max-Heap lưu nửa nhỏ hơn và Min-Heap lưu nửa lớn hơn, giữ kích thước 2 heap chênh nhau tối đa 1 phần tử → tìm trung vị trong O(1), chèn số mới trong O(log N)!

5. Cây Nhị Phân Tìm Kiếm (Binary Search Tree — BST)

                        
Symmetric Order, Search, Insert, Hibbard Deletion, Floor/Ceiling, Rank & 3 phép duyệt Pre/In/Post-order

                    

                

            


            
            

                

                    
Phần 1 · Định nghĩa & Giải thích Symmetric Order, Các thao tác & Duyệt cây

                


                

                    

                        
🌳 Định nghĩa BST (Symmetric Order)

                        
Là cây nhị phân trong đó tại MỌI nút x:

                        
Mọi khóa cây con TRÁI < x.key < Mọi khóa cây con PHẢI

                        
⚠️ Bẫy đề thi: Không được chỉ kiểm tra cha-con trực tiếp! Mọi nút trong cây con trái của x đều phải < x.key. Cách kiểm tra nhanh nhất: duyệt In-order phải ra dãy tăng dần nghiêm ngặt.

                    


                    

                        
🗑 Xóa nút trong BST (Hibbard Deletion)

                        
Tìm đến nút t cần xóa, chia 3 trường hợp:

                        
    
                            
  • 0 con (nút lá): Trả về null cho link của cha.
    • 
                            
  • 1 con: Trả về con duy nhất (t.left hoặc t.right) nối thẳng lên cha.
    • 
                            
  • 2 con: Tìm Successor x = min(t.right) (nhỏ nhất cây con phải), xóa min khỏi t.right bằng deleteMin(t.right), rồi đưa x lên thay vị trí của t.
    • 
                        

                    


                    

                        
🧭 3 Phép duyệt cây (Tree Traversals — O(N))

                        
    
                            
  • Pre-order (NLR): Gốc → Trái → Phải (Gốc đứng đầu tiên; dùng để copy cây hoặc biểu thức tiền tố).
    • 
                            
  • In-order (LNR): Trái → Gốc → Phải (Cho ra dãy khóa tăng dần trên BST!).
    • 
                            
  • Post-order (LRN): Trái → Phải → Gốc (Gốc đứng cuối cùng; dùng tính chiều cao, xóa cây, biểu thức hậu tố).
    • 
                        

                    

                


                

                    

                        
                            

                                Thao tác trên BST
                                Average Case (Chèn ngẫu nhiên N khóa)
                                Worst Case (Chèn dãy đã sắp xếp)
                                Giải thích nguyên lý
                            

                        
                        
                            

                                Search (get) / Insert (put)
                                ~ 1.39 lg N
                                O(N) (cây suy biến lệch hẳn 1 bên)
                                Số phép so sánh = 1 + depth(node). Tương ứng 1-1 với phân hoạch Quicksort!
                            

                            

                                Min / Max / Floor / Ceiling
                                O(log N)
                                O(N)
                                min: đi trái tận cùng; floor(k): số lớn nhất ≤ k.
                            

                            

                                Rank / Select
                                O(log N)
                                O(N)
                                Nhờ lưu thêm biến count = 1 + size(left) + size(right) tại mỗi Node.
                            

                            

                                Delete (Hibbard)
                                O(√N) (sau nhiều lần xóa)
                                O(N)
                                Vì luôn lấy successor bên phải nên sau nhiều lần chèn/xóa ngẫu nhiên cây bị lệch thành ~ √N.

6. Cây Nhị Phân Cân Bằng: AVL Tree & 2-3 / Red-Black BST

                        
Hệ số cân bằng Balance Factor, 4 trường hợp xoay (LL, RR, LR, RL) & Đối chiếu với Cây 2-3 / LLRB

                    

                

            


            
            

                

                    
Phần 1 · Định nghĩa & Giải thích Định nghĩa AVL Tree, 4 Trường hợp Xoay & So sánh với 2-3 / LLRB

                


                

                    

                        
⚖️ Định nghĩa Cây AVL (Adelson-Velsky & Landis)

                        
Cây AVL là một Binary Search Tree (BST) tự cân bằng sao cho tại MỌI nút v, chiều cao của cây con trái và cây con phải chênh lệch nhau không quá 1:

                        
Balance Factor: BF(v) = height(v.left) - height(v.right) ∈ {-1, 0, +1}

                        
    
                            
  • Nếu sau khi chèn hoặc xóa, tại nút z (tổ tiên thấp nhất bị lệch) có |BF(z)| == 2 → cây mất cân bằng tại z và được khôi phục bằng phép xoay (Rotation / Restructure) trong O(1).
    • 
                            
  • Chiều cao cây AVL có N nút luôn thỏa mãn h < 1.44 lg(N + 2) → đảm bảo Search, Insert, Remove đều là O(log N) trong trường hợp xấu nhất!
    • 
                        

                    


                    

                        
🔴⚫ Liên hệ với Cây 2-3 & Left-Leaning Red-Black BST (LLRB)

                        
Trong bộ tài liệu BinaryTree/, ngoài AVL Tree (cân bằng theo chiều cao), ta còn có:

                        
    
                            
  • 2-3 Search Tree / (2,4) Tree: Cho phép 1 nút chứa 1 hoặc 2 khóa (2-node, 3-node). Chèn vào 3-node tạo 4-node tạm rồi tách đẩy khóa giữa lên cha → mọi đường đến null có độ dài bằng nhau tuyệt đối!
    • 
                            
  • LLRB (Red-Black BST): Biểu diễn 1-1 của cây 2-3 bằng BST thường với cạnh ĐỎ nghiêng trái nối 2 khóa của 3-node. Chỉ dùng 3 phép biến đổi: (1) Đỏ phải → rotateLeft, (2) 2 Đỏ trái liên tiếp → rotateRight, (3) 2 con đều Đỏ → flipColors.
    • 
                        

                    

                


                
🔄 4 Trường hợp mất cân bằng trong AVL Tree & Cách xoay khôi phục (Slide 4-5, 33Z_AVLTrees.pdf)

                

                    

                        
1. Left-Left (LL Case)

                        
BF(z) = +2 và BF(z.left) ≥ 0 (Chèn vào cây con TRÁI của con TRÁI).

                        
➡ Xoay đơn: rotateRight(z)

                    

                    

                        
2. Right-Right (RR Case)

                        
BF(z) = -2 và BF(z.right) ≤ 0 (Chèn vào cây con PHẢI của con PHẢI).

                        
➡ Xoay đơn: rotateLeft(z)

                    

                    

                        
3. Left-Right (LR Case)

                        
BF(z) = +2 và BF(z.left) = -1 (Gấp khúc: TRÁI rồi PHẢI).

                        
➡ Xoay kép: rotateLeft(z.left) rồi rotateRight(z)

                    

                    

                        
4. Right-Left (RL Case)

                        
BF(z) = -2 và BF(z.right) = +1 (Gấp khúc: PHẢI rồi TRÁI).

                        
➡ Xoay kép: rotateRight(z.right) rồi rotateLeft(z)

                    

                


                

                    

                        
                            

                                Tiêu chí so sánh
                                BST thường
                                AVL Tree
                                2-3 Tree
                                Red-Black BST (LLRB)
                            

                        
                        
                            

                                Điều kiện cân bằng
                                Không cân bằng
                                |h(L) - h(R)| ≤ 1 tại mọi nút
                                Mọi lá ở cùng độ sâu tuyệt đối
                                Black-height bằng nhau, không có 2 cạnh đỏ liên tiếp
                            

                            

                                Chiều cao tối đa (Worst-case)
                                N - 1
                                ~ 1.44 lg N (cân bằng chặt nhất)
                                0.63 lg N .. lg N
                                ≤ 2 lg N
                            

                            

                                Search / Insert / Delete (Worst)
                                O(N)
                                O(log N)
                                O(log N)
                                O(log N)
                            

                            

                                Số phép xoay khi Insert / Delete
                                0
                                Insert: tối đa 1 xoay (đơn/kép);
Delete: có thể xoay O(log N) lần lên tới gốc		
                                Tách (split) / Gộp (merge) nút
