01 · Algorithm Analysis & Complexity

1. Phân tích thuật toán & Độ phức tạp (Complexity)

Mục tiêu của phân tích thuật toán là dự đoán thời gian chạy (Time Complexity) và dung lượng bộ nhớ (Space Complexity) khi kích thước đầu vào N tăng lớn, độc lập với phần cứng máy tính.

1.1 Mô hình chi phí & Các ký hiệu tiệm cận (~, Θ, O, Ω)

Mô hình chi phí (Cost Model): Chọn thao tác cơ bản chiếm phần lớn thời gian chạy (ví dụ: phép so sánh compareTo, phép truy cập mảng a[i]) và đếm tần suất thực hiện theo N.

① Ký hiệu Xấp xỉ Tilde: f(N) ~ g(N)

Nghĩa là limN→∞ f(N) / g(N) = 1. Giữ lại hệ số dẫn đầu của số hạng bậc cao nhất, bỏ các số hạng bậc thấp.

  • 2N³ - 15N² + N ~ 2N³
  • ½N(N - 1) ~ ½N²
  • lg(2N) / lg N = (1 + lg N)/lg N ~ 1
  • lg(N² + 1) / lg N ~ 2 lg N / lg N ~ 2

② Big-Theta: f(N) = Θ(g(N)) (Cận chặt / Order of Growth)

Tồn tại c₁, c₂ > 0 sao cho c₁·g(N) ≤ f(N) ≤ c₂·g(N) với mọi N ≥ N₀. Bỏ cả hệ số hằng dẫn đầu, dùng để phân loại bậc tăng trưởng (order of growth).

  • Nếu f(N) ~ c·g(N) (c > 0) thì f(N) = Θ(g(N)).
  • Ví dụ: ½N² - ½N = Θ(N²).

③ Big-Oh: f(N) = O(g(N)) (Cận trên — Upper Bound)

Tồn tại c > 0 sao cho f(N) ≤ c·g(N) với mọi N ≥ N₀. Không vượt quá tốc độ tăng của g(N).

  • Chính xác toán học (dùng trong bài thi): Nếu f(N) = 2N² + 2N thì f(N) thuộc cả O(N²), O(N³), O(2ⁿ) (vì đều là cận trên!).
  • Trong giao tiếp thường ngày, người ta hay dùng O(...) để chỉ worst-case, nhưng trong đề thi COS226 cần phân biệt rõ cận trên O và cận chặt Θ.

④ Big-Omega: f(N) = Ω(g(N)) (Cận dưới — Lower Bound)

Tồn tại c > 0 sao cho f(N) ≥ c·g(N) với mọi N ≥ N₀. Tăng ít nhất nhanh bằng g(N).

  • Chính xác toán học: Nếu f(N) = 2N² + 2N thì f(N) thuộc cả Ω(N²), Ω(N), Ω(log N), Ω(1).
  • f(N) = Θ(g(N)) khi và chỉ khi f(N) = O(g(N)) và f(N) = Ω(g(N)).
📌 Bẫy đề thi COS226 cực hay gặp: Cho hàm f(n) = n log²n + 3n√n - 5n. Vì √n = n^(0.5) >> log²n khi n → ∞, số hạng trội nhất là 3n√n = 3n^(1.5). Do đó:
• Xấp xỉ tilde: ~ 3n√n (nếu đáp án ghi ~ n√n là SAI vì thiếu hệ số 3!).
• Cận chặt: Θ(n√n). Cận trên đúng: O(n√n), O(n²), O(n³). Cận dưới đúng: Ω(n√n), Ω(n), Ω(log n).

1.3 Doubling Hypothesis & Phân tích bộ nhớ 64-bit (Memory Analysis)

⏱️ Giả thuyết Nhân đôi (Doubling Hypothesis)

Giả sử thời gian chạy tuân theo định luật lũy thừa T(N) ~ a·Nᵇ. Đo tỉ số khi tăng gấp đôi đầu vào:

T(2N) / T(N) ≈ 2ᵇ ⇒ b ≈ lg( T(2N) / T(N) )

  • Tỉ số ≈ 2 → b = 1 → tuyến tính ~ a·N
  • Tỉ số ≈ 4 → b = 2 → bậc hai ~ a·N²
  • Tỉ số ≈ 8 → b = 3 → bậc ba ~ a·N³

💾 Mô hình bộ nhớ Java 64-bit (Sedgewick)

  • Kiểu nguyên thủy: boolean, byte (1B); char, short (2B); int, float (4B); long, double (8B).
  • Object overhead: 16 bytes cho mỗi đối tượng.
  • Reference (con trỏ tham chiếu): 8 bytes.
  • Inner class (non-static): tốn thêm 8 bytes tham chiếu ẩn tới outer class!
  • Padding: tổng kích thước mỗi Object luôn làm tròn lên bội số của 8 bytes.
  • Mảng 1 chiều: 24 bytes header + N × kích_thước_phần_tử (làm tròn bội của 8).
Ví dụ tính bộ nhớ chuẩn đề thi (COS226): Cho lớp BST có private class Node (inner class non-static) gồm: Key key (8B ref), Value val (8B ref), Node parent, left, right (3 × 8B = 24B ref), int count (4B).
• Một đối tượng Node tốn: 16 (object overhead) + 8 (outer this ref) + 8 (key) + 8 (val) + 24 (3 links) + 4 (int) = 68 bytes → làm tròn lên bội của 8 là 72 bytes.
• Nếu Node là static class và chỉ có key, val, left, right, count: 16 + 8 + 8 + 8 + 8 + 4 = 52 → 56 bytes/node.
• Một Node của Singly Linked List (non-static, gồm Item item + Node next): 16 + 8 (outer) + 8 (item) + 8 (next) = 40 bytes/node.

02 · Stack (LIFO)

2. Stack — Cấu trúc Ngăn xếp

Nguyên lý: LIFO (Last-In, First-Out) — phần tử vào sau cùng sẽ được lấy ra đầu tiên. Mọi thao tác push (thêm), pop (lấy & xóa), peek (xem đỉnh) đều diễn ra tại một đầu duy nhất gọi là đỉnh (top).

2.1 Hai cách cài đặt Stack: Linked List vs Resizing Array

🔗 Cách 1: Singly Linked List (Danh sách liên kết đơn)

  • Đỉnh stack là đầu danh sách (first / top).
  • push(x): tạo node mới ở đầu danh sách (first).
  • pop(): lấy first.item, dời first = first.next.
  • Ưu điểm: Mọi thao tác tốn O(1) trong trường hợp xấu nhất (worst-case), không bao giờ phải resize.
  • Nhược điểm: Tốn bộ nhớ cho con trỏ và object header (~40 bytes/node trên JVM 64-bit), các node nằm rải rác kém thân thiện cache.

📦 Cách 2: Resizing Array (Mảng co giãn động)

  • Lưu phần tử trong mảng a[0..n-1], đỉnh stack tại a[n-1].
  • Khi đầy (n == a.length): nhân đôi kích thước mảng resize(2 * a.length).
  • Khi vơi còn 1/4 (n > 0 && n == a.length / 4): thu nhỏ một nửa resize(a.length / 2) (nếu giảm ở 1/2 sẽ bị thrashing O(N) mỗi bước khi xen kẽ push/pop ở ngưỡng nửa mảng!).
  • Tránh Loitering: sau khi pop() phải gán a[n] = null để Garbage Collector thu hồi bộ nhớ.
  • Ưu điểm: Chi phí O(1) khấu hao (amortized), tốn rất ít bộ nhớ (~8B–32B cho mỗi tham chiếu), rất nhanh nhờ bộ nhớ liên tục.
Linked List Stack:   top ──► [ 40 | •─]──► [ 30 | •─]──► [ 20 | •─]──► [ 10 | null ]
Resizing Array:      a[] = [ 10 | 20 | 30 | 40 | null | null | null | null ]   (n = 4, top = n-1 = 3)

03 · Queue (FIFO)

3. Queue — Cấu trúc Hàng đợi

Nguyên lý: FIFO (First-In, First-Out) — phần tử vào trước được lấy ra trước. Thêm ở cuối hàng (rear / last — enqueue) và lấy ra ở đầu hàng (front / first — dequeue).

3.1 Cài đặt Queue: Linked List vs Circular Resizing Array

Linked List Queue:
  first (front)                                 last (rear)
       ↓                                             ↓
    [ 10 | •─]──► [ 20 | •─]──► [ 30 | •─]──► [ 40 | null ]
  ◄── dequeue() lấy ở first                    enqueue() nối vào sau last ──►

Circular Array Queue (quấn vòng bằng phép chia dư % capacity):
  Chỉ số tiếp theo:  (idx + 1) % data.length
  Vị trí phần tử thứ i:  data[(front + i) % data.length]

3.2 Cài đặt Queue bằng 2 Stack (Amortized O(1))

Ý tưởng: Dùng 2 stack inStack (chuyên nhận enqueue) và outStack (chuyên phục vụ dequeue/peek). Khi outStack rỗng mà cần dequeue, ta đổ toàn bộ phần tử từ inStack sang outStack (thứ tự LIFO bị đảo ngược 2 lần thành FIFO!). Mỗi phần tử chỉ được push/pop tối đa 2 lần → O(1) amortized.

4. Hàng đợi ưu tiên (Priority Queue) & Binary Heap

Khác với Stack (lấy phần tử mới nhất) và Queue (lấy phần tử cũ nhất), Priority Queue luôn lấy ra phần tử có độ ưu tiên cao nhất: MaxPQ hỗ trợ insert và delMax; MinPQ hỗ trợ insert và delMin.

4.1 Biểu diễn Binary Heap bằng mảng & Phép swim / sink

Định nghĩa Binary Heap: Là một cây nhị phân hoàn chỉnh (complete binary tree) (mọi tầng đều đầy trừ tầng đáy được điền từ trái sang phải) thỏa mãn thứ tự Heap (heap-ordered): trong Max-Heap, khóa của mỗi node ≥ khóa của 2 con nó (root tại pq[1] là phần tử lớn nhất).

📐 Chỉ số mảng 1-based (Chuẩn Sedgewick, bỏ trống pq[0])

  • Root nằm tại pq[1], các phần tử từ pq[1..N].
  • Node cha của k: k / 2.
  • Hai con của k: 2k (trái) và 2k + 1 (phải).
  • Các node lá (không có con): từ chỉ số ⌊N/2⌋ + 1 đến N.

📐 Chỉ số mảng 0-based (Bài 2.4.10 — đặt root tại pq[0])

  • Root nằm tại pq[0], các phần tử từ pq[0..N-1].
  • Node cha của k: (k - 1) / 2.
  • Hai con của k: 2k + 1 (trái) và 2k + 2 (phải).
  • Các node trong (internal nodes): từ 0 đến ⌊N/2⌋ - 1.

  • Thêm phần tử insert(x): Đặt x vào cuối mảng pq[++N] = x, rồi gọi swim(N) để đẩy lên (tối đa ⌊lg N⌋ phép so sánh).
  • Xóa phần tử lớn nhất delMax(): Lấy max = pq[1], đổi chỗ exch(1, N--), gán pq[N+1] = null, rồi gọi sink(1) để đẩy phần tử mới ở gốc xuống đúng chỗ (tối đa 2⌊lg N⌋ phép so sánh vì mỗi tầng phải so 2 con 2k và 2k+1 rồi so với cha).

4.2 Xây dựng Heap Bottom-Up O(N) & Các tính chất hay hỏi thi

  • Build Heap Bottom-Up (Floyd): Cho mảng N phần tử bất kỳ, gọi sink(k) ngược từ k = N/2 về 1 (bỏ qua toàn bộ các lá vì lá đã là heap kích thước 1). Chi phí: dưới 2N phép so sánh và dưới N phép đổi chỗ → O(N) tuyến tính (nhanh hơn chèn từng phần tử từ đầu tốn O(N log N)).
  • Mảng đã sắp xếp giảm dần có phải Max-Heap không? (Bài 2.4.4): CÓ! Vì với mọi k ≥ 1, ta luôn có k < 2k < 2k+1 nên a[k] ≥ a[2k] ≥ a[2k+1].
  • Vị trí của phần tử lớn thứ k trên Max-Heap (Bài 2.4.7):
    • Lớn thứ 1 (max): chỉ ở vị trí 1.
    • Lớn thứ 2: chỉ có thể ở vị trí 2 hoặc 3 (con trực tiếp của root).
    • Lớn thứ 3: có thể ở các vị trí 2, 3, 4, 5, 6, 7 (tầng 1 và tầng 2, tức ≤ 2³ - 1 = 7).
    • Tổng quát: phần tử lớn thứ k chỉ có thể nằm ở các độ sâu ≤ k - 1 (chỉ số ≤ 2ᵏ - 1). Phần tử nhỏ nhất (min) của Max-Heap bắt buộc phải là một node lá (chỉ số từ ⌊N/2⌋ + 1 đến N).
  • Kiểm tra một mảng pq[1..N] có phải Min-Heap trong O(N) (Bài 2.4.15): Duyệt k từ 1 đến N/2, kiểm tra pq[k] ≤ pq[2k] và (nếu 2k+1 ≤ N) pq[k] ≤ pq[2k+1].

05 · Binary Search Tree (BST)

5. Cây Nhị Phân Tìm Kiếm (Binary Search Tree — BST)

Định nghĩa (Symmetric Order): Một cây nhị phân tìm kiếm (BST) là một cây nhị phân mà mỗi node x có một khóa Comparable sao cho MỌI khóa trong cây con trái < x.key < MỌI khóa trong cây con phải.

⚠️ Bẫy đề thi "Đây có phải BST hợp lệ?": Không được chỉ kiểm tra từng cặp cha–con! Ví dụ: Root = 25, con phải của 25 là 42, con trái của 42 là 20. Mặc dù 20 < 42, nhưng 20 lại nằm trong cây con phải của 25 mà 20 < 25 → SAI (Không phải BST)!
Cách kiểm tra nhanh nhất khi làm bài: Đọc thứ tự In-order (Trái → Gốc → Phải), nếu dãy khóa thu được tăng dần nghiêm ngặt thì là BST hợp lệ.

5.1 Các thao tác tìm kiếm, chèn, và thứ tự trên BST

  • Tìm kiếm get(key) & Chèn put(key, val): Bắt đầu từ root. Nhỏ hơn thì rẽ trái, lớn hơn thì rẽ phải, bằng thì tìm thấy (hoặc cập nhật value). Khi gặp null: get trả về null (search miss); put tạo node mới tại đúng chỗ null đó (node mới chèn luôn là lá!).
  • Số phép so sánh: Bằng 1 + depth(node).
    • Best case (cây cân bằng hoàn hảo): chiều cao h ≈ lg N.
    • Average case (chèn ngẫu nhiên N khóa): số phép so sánh trung bình ~ 2 ln N ≈ 1.39 lg N (tương ứng 1–1 với Quicksort partitioning!).
    • Worst case (chèn dãy đã tăng dần hoặc giảm dần): cây suy biến thành danh sách liên kết, chiều cao h = N - 1 → O(N).
  • min() / max(): Đi sang trái tận cùng (cho đến khi x.left == null) / đi sang phải tận cùng.
  • floor(key) (lớn nhất ≤ key):
    • Nếu key == x.key → trả về x.key.
    • Nếu key < x.key → floor bắt buộc phải nằm ở cây con trái.
    • Nếu key > x.key → x.key là ứng viên, nhưng thử tìm xem trong cây con phải có khóa nào ≤ key không; nếu có thì lấy kết quả bên phải, nếu không thì trả về x.key.
  • rank(key) (số khóa < key) & select(k) (khóa nhỏ thứ k, tính từ 0): Duy trì biến x.count = 1 + size(x.left) + size(x.right) ở mỗi node, thực hiện trong O(h).

5.2 Xóa node trong BST (Hibbard Deletion) & 4 Cách duyệt cây

🗑 Hibbard Deletion: 3 trường hợp khi xóa node t

  1. Node lá (0 con): Trả về null cho link của cha.
  2. Node có 1 con: Trả về link trỏ tới đứa con duy nhất đó để nối thẳng lên cha.
  3. Node có 2 con (QUAN TRỌNG NHẤT):
    • Tìm Successor x = min(t.right) (node trái nhất của cây con phải — không có con trái) hoặc Predecessor = max(t.left).
    • Xóa min khỏi cây con phải: x.right = deleteMin(t.right).
    • Gán lại con trái: x.left = t.left, rồi đặt x thay vào vị trí của t.

Lưu ý: Hibbard deletion không đối xứng nên sau nhiều lần chèn/xóa ngẫu nhiên, chiều cao cây trung bình bị tăng lên ~ √N.

🧭 4 Cách duyệt cây (Tree Traversals — O(N))

  • Pre-order (NLR — Tiền thứ tự): Gốc → Trái → Phải. Gốc luôn đứng đầu tiên. Dùng để clone cây, lưu cấu trúc cây.
  • In-order (LNR — Trung thứ tự): Trái → Gốc → Phải. Với mọi BST (thường, AVL, Red-Black), In-order luôn cho dãy khóa tăng dần!
  • Post-order (LRN — Hậu thứ tự): Trái → Phải → Gốc. Gốc luôn đứng cuối cùng. Dùng để tính chiều cao height(x), giải phóng bộ nhớ.
  • Level-order (BFS — Theo tầng): Dùng Queue duyệt từ trên xuống dưới, trái sang phải.

6. Cây Tìm Kiếm Cân Bằng: AVL Tree, 2-3 Tree & Red-Black BST

Để khắc phục nhược điểm suy biến O(N) của BST thường khi dữ liệu đầu vào có thứ tự, các cây tìm kiếm cân bằng tự động tái cấu trúc sau khi chèn/xóa để đảm bảo chiều cao luôn O(log N) trong mọi trường hợp.

6.1 Cây AVL (AVL Tree) & Bốn Trường Hợp Xoay Cân Bằng

  • Định nghĩa: Cây AVL là một BST mà tại mọi node v, độ chênh lệch chiều cao giữa cây con trái và cây con phải không vượt quá 1:
    Hệ số cân bằng (Balance Factor): BF(v) = height(v.left) - height(v.right) ∈ {-1, 0, +1}.
  • Chiều cao tối đa: Cây AVL có N node luôn có chiều cao h ≤ 1.44 lg(N + 2) (chứng minh qua dãy Fibonacci N(h) = 1 + N(h-1) + N(h-2)). Do đó find, insert, remove đều đảm bảo O(log N) worst-case!
  • Quy trình chèn vào AVL: Chèn như BST thường ở lá, sau đó trên đường đệ quy quay ngược lên gốc, cập nhật height từng node. Gặp node mất cân bằng đầu tiên z (có |BF(z)| == 2), gọi y là con cao hơn của z và x là con cao hơn của y. Có đúng 4 trường hợp (LL, RR, LR, RL):

1️⃣ Left–Left (LL): Lệch Trái–Trái (BF(z) > 1 và BF(y) ≥ 0)

x nằm ở nhánh trái của con trái y → Chỉ cần 1 phép Xoay Phải đơn: rotateRight(z).

2️⃣ Right–Right (RR): Lệch Phải–Phải (BF(z) < -1 và BF(y) ≤ 0)

x nằm ở nhánh phải của con phải y → Chỉ cần 1 phép Xoay Trái đơn: rotateLeft(z).

3️⃣ Left–Right (LR): Gấp khúc Trái–Phải (BF(z) > 1 và BF(y) < 0)

Xoay kép (2 bước): (1) Xoay trái tại con trái z.left = rotateLeft(z.left) để biến thành dạng LL; (2) Xoay phải tại z: rotateRight(z).

4️⃣ Right–Left (RL): Gấp khúc Phải–Trái (BF(z) < -1 và BF(y) > 0)

Xoay kép (2 bước): (1) Xoay phải tại con phải z.right = rotateRight(z.right) để biến thành dạng RR; (2) Xoay trái tại z: rotateLeft(z).

• Khi Insert: Sau khi thực hiện đúng 1 lần xoay (đơn hoặc kép) tại node mất cân bằng thấp nhất z, chiều cao cây con gốc z trở lại bằng trước khi chèn → toàn bộ các tổ tiên phía trên đều tự động cân bằng! (Tối đa 1 lần restructure).
• Khi Remove (Xóa): Sau khi xoay tại z, chiều cao cây con có thể giảm 1, làm mất cân bằng một node tổ tiên cao hơn → phải tiếp tục kiểm tra và xoay dọc đường lên đến tận root (tối đa O(log N) lần xoay).

6.3 Cây 2-3 (2-3 Search Tree) & Left-Leaning Red-Black BST (LLRB)

Trong giáo trình Sedgewick (Chương 3.3), cây cân bằng được dạy qua Cây 2-3 và cài đặt bằng Cây Đỏ-Đen nghiêng trái (LLRB):

  • Cây 2-3 (2-3 Search Tree): Cho phép 2 loại node:
    • 2-node: chứa 1 khóa, 2 nhánh con (như BST).
    • 3-node: chứa 2 khóa a < b, 3 nhánh con (< a, nằm giữa (a, b), và > b).
    • Cơ chế chèn: Chèn khóa mới vào node lá ở đáy. Nếu lá là 3-node thì tạo thành 4-node tạm [a | b | c] → lập tức tách (split) thành hai 2-node a và c, đồng thời đẩy khóa giữa b lên cha. Cây chỉ tăng chiều cao khi root bị tách → mọi đường từ root tới null có độ dài bằng nhau tuyệt đối! Chiều cao cây 2-3 luôn nằm trong [⌊log₃ N⌋ ≈ 0.63 lg N, ⌊lg N⌋].
  • Tương ứng 1–1 giữa Cây 2-3 và LLRB: Mỗi 3-node [a | b] được biểu diễn trong BST bằng 2 node nối bởi cạnh ĐỎ nghiêng trái (khóa lớn hơn b làm cha ĐEN, khóa nhỏ hơn a làm con trái ĐỎ).
  • 3 Bất biến của LLRB:
    1. Mọi cạnh ĐỎ đều nghiêng sang trái (không có con phải đỏ).
    2. Không có node nào gắn với 2 cạnh ĐỎ liên tiếp.
    3. Perfect Black Balance: mọi đường đi từ root tới null đi qua cùng một số lượng cạnh ĐEN (= chiều cao cây 2-3). Chiều cao LLRB luôn ≤ 2 lg N.

7. Các thuật toán sắp xếp

Tất cả code dưới đây dùng chung các hàm tiện ích less và exch (giống sách Sedgewick):

Stable (ổn định): các phần tử có key bằng nhau giữ nguyên thứ tự tương đối ban đầu (quan trọng khi sắp xếp theo nhiều khóa). In-place: chỉ dùng thêm O(1) hoặc O(log N) bộ nhớ.
Cận dưới: mọi thuật toán sắp xếp dựa trên so sánh cần ít nhất lg(N!) ~ N lg N phép so sánh trong trường hợp xấu nhất (cây quyết định có N! lá).

7.1 Selection Sort (Sắp xếp chọn)

Ý tưởng: ở vòng thứ i, tìm phần tử nhỏ nhất trong a[i..N-1] rồi đổi chỗ với a[i].

  • So sánh: ~N²/2 (luôn luôn, kể cả mảng đã sắp xếp). Đổi chỗ: đúng N lần, ít nhất trong các thuật toán.
  • Không ổn định, in-place. Thời gian không phụ thuộc input.
[ 5 3 8 1 9 2 ]  → min=1, đổi với 5 → [ 1 | 3 8 5 9 2 ]
                  → min=2, đổi với 3 → [ 1 2 | 8 5 9 3 ]
                  → min=3, đổi với 8 → [ 1 2 3 | 5 9 8 ] ...

7.2 Insertion Sort (Sắp xếp chèn)

Ý tưởng: giống xếp bài trên tay, lấy a[i] và chèn ngược về đúng chỗ trong phần đã sắp xếp a[0..i-1] bằng cách đổi chỗ liên tiếp sang trái.

  • Trung bình: ~N²/4 so sánh và ~N²/4 đổi chỗ. Xấu nhất (mảng giảm dần): ~N²/2. Tốt nhất (đã sắp xếp): N−1 so sánh, 0 đổi chỗ.
  • Số lần đổi chỗ = số nghịch thế (inversions). Với mảng gần như đã sắp xếp (số nghịch thế ≤ cN) → tuyến tính.
  • Ổn định, in-place, rất nhanh với mảng nhỏ (Mergesort/Quicksort chuyển sang insertion khi mảng con ≤ ~10 phần tử).

7.3 Shell Sort

Ý tưởng: insertion sort với bước nhảy h giảm dần (h-sort). Mảng h-sorted = h dãy con xen kẽ đều đã sắp xếp. Bước lớn đưa phần tử đi xa nhanh, bước cuối h = 1 là insertion sort trên mảng gần sắp xếp.

  • Dãy Knuth: h = 3h + 1 → 1, 4, 13, 40, 121, 364…
  • Xấu nhất với 3x+1: O(N^(3/2)). Thực nghiệm khoảng N^1.25. Chưa có công thức chính xác cho trường hợp trung bình.
  • Không ổn định, in-place, code ngắn → hay dùng trong hệ nhúng.

7.4 Merge Sort (Sắp xếp trộn)

Chia để trị: chia đôi mảng, sắp xếp đệ quy từng nửa, rồi trộn (merge) hai nửa đã sắp xếp bằng mảng phụ aux.

  • So sánh: từ ~½N lg N đến N lg N. Truy cập mảng ≤ 6N lg N. Đảm bảo O(N log N) mọi trường hợp.
  • Bộ nhớ phụ O(N) (không in-place). Ổn định (khi bằng nhau lấy từ nửa trái trước).
  • Truy hồi: C(N) = 2C(N/2) + N → N lg N.
  • Cải tiến: (1) insertion sort cho mảng con ≤ 7; (2) bỏ qua merge nếu a[mid] ≤ a[mid+1] → mảng đã sắp xếp chỉ mất O(N); (3) đổi vai trò a/aux để bỏ bước copy.
  • Java dùng TimSort (merge + insertion) cho Arrays.sort(Object[]) vì cần ổn định.

7.5 Quick Sort (Sắp xếp nhanh)

Chia để trị: xáo trộn mảng, chọn pivot a[lo], phân hoạch (partition) sao cho bên trái ≤ pivot ≤ bên phải, rồi đệ quy hai phần.

  • Trung bình: ~2N ln N ≈ 1.39 N lg N so sánh, ~⅓N ln N đổi chỗ. Nhiều so sánh hơn mergesort 39% nhưng nhanh hơn trong thực tế vì ít di chuyển dữ liệu và thân thiện cache.
  • Xấu nhất: ~½N² (pivot luôn là min/max, ví dụ mảng đã sắp xếp mà không shuffle) → vì vậy phải shuffle trước.
  • Tốt nhất: ~N lg N (pivot luôn chia đôi).
  • In-place (stack đệ quy O(log N) kỳ vọng), không ổn định.
  • Cải tiến: insertion sort cho mảng con nhỏ; chọn pivot là median-of-3; 3-way partition khi có nhiều key trùng.

Partition kiểu Sedgewick (2 con trỏ)

  1. i chạy từ trái sang khi a[i] < pivot.
  2. j chạy từ phải sang khi a[j] > pivot.
  3. Nếu i >= j thì dừng; ngược lại đổi a[i] với a[j], lặp lại.
  4. Cuối cùng đổi a[lo] (pivot) với a[j], trả về j.
pivot = K
 K  R  A  T  E  L  E  P  U  I  M  Q  C  X  O  S
    i→                                      ←j     i dừng ở R (≥K), j dừng ở C (≤K) → đổi
 K  C  A  T  E  L  E  P  U  I  M  Q  R  X  O  S
          i                       j              i ở T, j ở I → đổi ... đến khi i >= j
 E  C  A  I  E  K  L  P  U  T  M  Q  R  X  O  S  ← cuối: đổi pivot với a[j]
 └── ≤ K ──┘   ↑   └────────── ≥ K ──────────┘
Vì sao Hoare/Sedgewick partition dừng khi bằng pivot? Nếu mảng toàn key bằng nhau mà không dừng (dùng <=), partition sẽ lệch hẳn về một phía → ~½N². Dừng khi bằng nhau dù đổi chỗ thừa nhưng chia đôi mảng đều → ~N lg N. 3-way quicksort còn tốt hơn: với mảng có ít key khác nhau, chi phí là O(N) tuyến tính.

7.6 Heap Sort

Hai pha: (1) Xây max-heap bottom-up trong O(N); (2) lặp lại: đổi a[1] (max) với phần tử cuối, giảm kích thước heap, sink(1).

  • Xây heap ≤ 2N so sánh; sắp xếp ≤ 2N lg N so sánh. Đảm bảo O(N log N) và in-place O(1): thuật toán duy nhất trong bảng có cả hai.
  • Nhược: không ổn định, vòng lặp trong dài hơn quicksort, truy cập bộ nhớ nhảy cóc (kém cache).
  • Introsort (C++ std::sort): quicksort, chuyển sang heapsort khi đệ quy quá sâu (2 lg N), insertion cho mảng nhỏ.

Heap SortSau pha heapify: a[0] là max và thỏa mãn a[k] ≥ a[2k+1], a[2k+2]. Đang sort: các phần tử lớn nhất nằm ở cuối mảng tăng dần.

09 · Exam Tips

9. Mẹo làm bài & bẫy hay gặp

📈 Complexity

  • Vòng i *= 2 hoặc i /= 2 → log N.
  • Vòng trong chạy i lần với i giảm một nửa → tổng 2N, không phải N log N.
  • j chạy từ i+1 → ~N²/2, vẫn là O(N²).
  • Gọi s.length() / substring / nối chuỗi trong vòng lặp có thể ẩn thêm một chi phí O(N).

📚 Stack / Queue

  • Stack mảng: gấp đôi khi đầy, giảm nửa khi còn ¼.
  • Pop xong gán null (loitering).
  • Queue linked list: enqueue vào queue rỗng phải gán cả first; dequeue phần tử cuối phải gán last = null.
  • Kiểm tra dãy pop hợp lệ bằng cách mô phỏng.

⛰ Heap

  • Chỉ số từ 1: cha k/2, con 2k, 2k+1.
  • sink đổi với con lớn hơn (max-heap).
  • Xây heap bottom-up là O(N), chèn từng phần tử là O(N log N).
  • Heap không phải BST, tìm một key bất kỳ tốn O(N).

🌳 BST / AVL

  • Phần tử đầu tiên được chèn là root.
  • Xóa node có 2 con: successor = min của cây con phải.
  • Inorder của BST luôn tăng dần.
  • AVL: tìm node mất cân bằng thấp nhất trên đường từ node mới chèn lên; LL/RR xoay đơn, LR/RL xoay kép.
  • Chèn dãy tăng dần vào BST thường → cây suy biến; vào AVL → vẫn cân bằng.

🔀 Sorting

  • Nhận diện trạng thái trung gian: Selection: phần đầu đã sắp xếp và là các phần tử nhỏ nhất. Insertion: phần đầu đã sắp xếp nhưng chưa chắc là nhỏ nhất. Heap sort: phần cuối mảng là các phần tử lớn nhất.
  • Merge sort bottom-up: các khối kích thước 2, 4, 8 lần lượt được sắp xếp.
  • Quick sort sau partition: pivot đứng đúng vị trí cuối cùng.
  • Ổn định: Insertion, Merge, Counting, Radix. Không ổn định: Selection, Shell, Quick, Heap.

🧮 Số liệu cần thuộc

  • Selection: ~N²/2 so sánh, N đổi chỗ.
  • Insertion: ~N²/4 trung bình, số đổi chỗ = số nghịch thế.
  • Merge: ≤ N lg N so sánh, ≤ 6N lg N truy cập mảng.
  • Quick: ~1.39 N lg N trung bình, ~N²/2 xấu nhất.
  • Heap: ≤ 2N (xây) + 2N lg N (sắp xếp).
  • BST ngẫu nhiên: ~1.39 lg N; AVL ≤ 1.44 lg N; LLRB ≤ 2 lg N.
